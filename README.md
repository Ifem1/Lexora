# Lexora — GenLayer-Native Arbitration dApp

Lexora is a decentralised, AI-powered dispute-resolution protocol built on [GenLayer](https://genlayer.com). It enables two parties to open an arbitration case, submit claims, evidence, and responses, and receive a structured ruling generated by an AI arbitrator whose output is verified via GenLayer's optimistic-consensus validator network.

## Quick Start

### Prerequisites

- Node.js 20+
- npm 10+
- A browser wallet (MetaMask, Rabby, etc.)
- Access to GenLayer Testnet or a local GenLayer node

### Installation

```bash
git clone <repo-url>
cd Lexora
npm install
```

### Environment Variables

Copy `.env.local` (already provided) and fill in your deployed contract address:

```
NEXT_PUBLIC_CONTRACT_ADDRESS=<your deployed LexoraArbitration address>
NEXT_PUBLIC_GENLAYER_RPC_URL=https://studio.genlayer.com/api
NEXT_PUBLIC_CHAIN_ID=61999
NEXT_PUBLIC_DEV_MODE=true
```

- `NEXT_PUBLIC_CONTRACT_ADDRESS` — leave blank during local dev; the app will operate in mock mode when `NEXT_PUBLIC_DEV_MODE=true`.
- `NEXT_PUBLIC_CHAIN_ID` — `61999` for localnet, `961` for GenLayer Testnet.

### Development Server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

### Production Build

```bash
npm run build
npm start
```

## GenLayer Contract Deployment

The arbitration logic lives in `contracts/LexoraArbitration.py`.

### Using GenLayer Studio

1. Visit [https://studio.genlayer.com](https://studio.genlayer.com).
2. Create a new project and paste the contents of `contracts/LexoraArbitration.py`.
3. Deploy to the simulator or testnet.
4. Copy the deployed contract address into `NEXT_PUBLIC_CONTRACT_ADDRESS` in `.env.local`.

### Using the GenLayer CLI

```bash
pip install genlayer-cli
genlayer deploy contracts/LexoraArbitration.py --network testnet
```

Follow the CLI prompts to fund your account and confirm deployment.

## Framework Library Overview

Lexora ships a built-in library of arbitration frameworks in `src/lib/arbitration/frameworks.ts`. Each framework defines:

- **`id`** — machine-readable identifier (e.g. `COMMERCIAL_V1`)
- **`name`** — human-readable display name
- **`description`** — scope and purpose
- **`rules`** — ordered list of clauses the AI uses to adjudicate
- **`allowedOutcomes`** — subset of outcome types permitted under this framework
- **`remediationGuidelines`** — constraints on remedies (e.g. max monetary award)

You can extend the library by adding entries to the `FRAMEWORKS` array. The AI prompt in `contracts/LexoraArbitration.py` dynamically receives the active framework ID and applies the corresponding ruleset.

## Architecture Overview

```
┌────────────────────────────────────────────────────────────┐
│                      Next.js Frontend                      │
│  ┌──────────┐  ┌──────────────┐  ┌──────────────────────┐ │
│  │  Pages   │  │  Components  │  │  src/lib (utilities) │ │
│  │ /app/... │  │ cases/       │  │  arbitration/        │ │
│  │          │  │ evidence/    │  │  genlayer/           │ │
│  │          │  │ ruling/      │  │  wallet/             │ │
│  └────┬─────┘  └──────────────┘  └──────────────────────┘ │
│       │  Wagmi hooks + TanStack Query                      │
└───────┼────────────────────────────────────────────────────┘
        │ JSON-RPC (viem transport)
        ▼
┌───────────────────────────────┐
│   GenLayer Node / Testnet     │
│  ┌─────────────────────────┐  │
│  │  LexoraArbitration.py   │  │
│  │  (Intelligent Contract) │  │
│  │                         │  │
│  │  Validator 1 ──┐        │  │
│  │  Validator 2 ──┤ Opt.   │  │
│  │  Validator N ──┘ Consns │  │
│  └─────────────────────────┘  │
└───────────────────────────────┘
```

**Key flows:**

1. **Case creation** — party A calls `create_case`; both parties' addresses are indexed.
2. **Claim / response** — sequential write calls update case status and store content hashes.
3. **Evidence** — either party may call `submit_evidence` to update the Merkle root.
4. **Ruling** — `request_ruling` triggers a non-deterministic AI call across all validators; optimistic consensus produces a verified ruling stored on-chain.
5. **Accept / Appeal** — parties accept or appeal; appeals trigger a second non-deterministic call.
